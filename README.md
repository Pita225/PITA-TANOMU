# PITA_タノム

店舗間で、商品を選択して発注し、発注先店舗が受注内容を確認できる最小構成のWebアプリです。

## 起動方法

PowerShellでこのフォルダを開き、次を実行します。

```powershell
python -m pip install -r requirements.txt
python app.py
```

ブラウザで <http://127.0.0.1:5000> を開いてください。同じネットワーク内の端末から使う場合は、`app.run(debug=True, host="0.0.0.0")` に変更し、PCのIPアドレスへアクセスします。

初回アクセス時は管理者がまだ存在しないため、初期管理者作成画面が表示されます。任意のログインIDと8文字以上のパスワードを設定してください。この画面は管理者作成後には使用できません。管理者は「アカウント」画面から既存店舗のログインアカウントを作成できます。

パスワードはSQLiteにハッシュで保存され、平文では保存されません。セッション署名鍵は `SECRET_KEY` 環境変数を設定すると再起動後も固定できます。設定しない場合は安全な乱数が起動時に生成されるため、アプリを再起動すると再ログインが必要です。

## ログイン情報を忘れた場合

店舗アカウントと社長確認用アカウントは、管理者の「アカウント」画面で現在のログインIDを確認できます。同じ画面からログインID変更、パスワード再設定、停止、再開も行えます。既存パスワードを表示する機能はありません。

通常管理者がログインできない場合は、公開画面から任意の人が再設定することはできません。Renderに設定している `SECRET_KEY` を知っている管理責任者が、ローカル環境で次を実行します。

```powershell
python admin_recovery.py
```

画面に従ってRenderの `SECRET_KEY`、新しい管理者ログインID、新しいパスワードを入力します。生成された復旧トークンを15分以内に `https://＜Renderのホスト名＞/admin-recovery` へ入力してください。トークンには新しいパスワードそのものではなくWerkzeugのパスワードハッシュが含まれ、Renderの `SECRET_KEY` による署名が一致しないトークンは拒否されます。トークンは1回だけ使用でき、復旧に成功すると復旧前の全管理者セッションが無効になります。

復旧後は古いログインID・パスワードではログインできません。復旧トークンは管理者パスワードと同様に扱い、第三者へ共有しないでください。Render Free Web ServiceはShell／SSHを利用できないため、この署名済みトークン方式を使用します。

## データベース

初回起動時に `pita_tanom.db` が自動作成され、店舗3件・商品6件の初期データが入ります。初期状態に戻す場合は次を実行します（既存の発注データは消えます）。

```powershell
flask --app app init-db
```

店舗や商品は、初心者でも変更しやすいように [seed.sql](seed.sql) にまとめています。変更後に上記の初期化コマンドを実行してください。テーブル構造は [schema.sql](schema.sql) にあります。

通常の店舗追加・編集・停止・再開・削除は、画面上部の「店舗管理」から行えます。停止・削除した店舗は新しい発注の選択肢に表示されません。削除は過去の発注履歴を保つ論理削除です。

商品を受け取った発注元店舗は、画面上部の「受取確認」から発注を選びます。届いた数量には発注数量があらかじめ入力されており、差がある場合だけ修正します。数量差異がある場合は発注先（商品の送付元）の確認待ちとなり、送付元が「受注を確認」から承認すると最終受取数量が確定します。

注文外商品が届いた場合は受取確認画面で商品・数量を追加し、「返品する」または「受け取る」を選びます。返品は「返品予定 → 返品済み → 返品完了」、受取希望は「送付元承認待ち → 受取確定」として履歴に残ります。元の発注明細、実際に届いた数量、最終受取数量は別々に保存されます。

トップ画面には「発注・受取・承認済・未承認」の件数が表示されます。「未承認」は商品単位の処理件数で、受取確認、数量差異承認、注文外商品承認、返品処理、返品確認の各待ち状態を含みます。カードを押すと、次に処理する店舗と操作先が分かる一覧を表示します。

画面上部の「商品管理」では、商品、大分類・中分類、単位を管理できます。商品には任意で5MB以下のPNG・JPEG・GIF・WebP画像を1枚登録でき、画像は `static/uploads` に保存されます。既存商品は初回移行時に「未分類」へ割り当てられ、既存の単位と単価はそのまま保持されます。発注画面では分類と商品名で絞り込みでき、入力中の小計も表示されます。

# トレーニング分離・小数数量・保全機能

商品・分類・単位には `production` / `training` の環境スコープがあります。既存商品は安全な起動時マイグレーションで本番として保持され、別IDのトレーニング用マスタが一度だけ複製されます。社長確認用アカウントはトレーニング側の業務管理（商品、分類、単位、発注、受取、承認、訂正、集計、CSV）を操作できますが、本番データ、店舗管理、アカウント管理、トレーニングリセットにはアクセスできません。

単位ごとに数量の小数桁を0～2で設定できます。数量は互換表示用の値に加えて100倍の整数を正本として保存し、受取差異判定・返品・訂正・集計・CSVで固定小数として扱います。`kg` の初期値は小数第2位、その他の既存単位は整数です。

バックアップと監査スナップショットは初期値が完全OFFです。

```env
BACKUP_ENABLED=false
AUDIT_SNAPSHOT_ENABLED=false
```

将来有効化する場合は、永続ディスク等を指す `BACKUP_STORAGE_PATH` と `AUDIT_STORAGE_PATH` を設定し、`BACKUP_ENABLED=true` / `AUDIT_SNAPSHOT_ENABLED=true` にします。SQLiteバックアップは `flask backup` からSQLite Backup API、整合性検査、重要テーブルのUTF-8 BOM付きCSV出力を実行します。監査は重要操作をDB検索可能な構造化行として保存し、店舗／年／月／操作種別のHTMLスナップショットも生成します。保存物には個人情報・認証情報が含まれ得るためGitへ追加しないでください。
